# Architecture notes

`FrameReader` owns incremental decoding; `Trajectory` combines it with immutable topology metadata. Execution resets the reader, validates strictly increasing timestamps, evaluates predicate sources once per frame, and updates an `EventExtractor` state machine per source. A per-frame value cache is keyed by canonical observable identity, so repeated and symmetrically reversed observables are computed once even when multiple comparisons consume them. Only completed interval events are retained.

`Engine` caches parsed and topology-resolved `ExecutionPlan` values by exact query text. Each topology receives an immutable cache identity; moving an engine to a different topology invalidates its existing plans. The Python native trajectory session owns one engine, so repeated `query` and `explain` calls share the cache without global state. Frame predicates and event extractors remain execution-local and are recreated for every trajectory scan.

The parser emits typed AST nodes and performs dimensional validation. The planner resolves every required selection early, reports zero-match errors before trajectory scanning, and records unique observables. Temporal evaluation is a separate algebra over `Event` values, keeping molecular geometry unaware of relations such as `FOLLOWED_BY`.

Future geometry kernels should replace implementations, not interfaces. Full three-vector frame cells select orthorhombic or triclinic nearest-image geometry automatically. Radius of gyration receives the topology bond graph and reconstructs connected molecules before evaluation. The optional chemfiles adapter implements `FrameReader` for XTC, TRR, and DCD without exposing chemfiles types to the parser, planner, engine, or Python convenience layer. It carries cell and time metadata forward so periodic data can never silently degrade into non-periodic geometry.
